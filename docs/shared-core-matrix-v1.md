# 共同协议下的核心对照矩阵

本阶段从训练方案选择回到方法效果验证。两个项目采用共同 5% 用户队列、batch=256、两类学习率 0.001、单轮下游训练；首先运行 seed=42，整组审计后再扩展到 2026、3407。当前队列已启动，尚无本轮完整对照结论。

## 第一部分：内容怎样进入推荐模型

|方法|配置索引|要回答的问题|
|---|---|---|
|ID 基线|C0|没有新增内容分支时的参照|
|直接内容向量融合|C2|直接引入向量是否有效|
|相似度分桶统计|C3|相似度分布是否提供有用信息|
|预训练内容知识接入|C5|单独接入 MAKE 知识的效果|
|相似度统计 + 预训练内容知识|C6|两类信息是否互补|
|逐行为相似度侧信息|C7|保留逐条相似度与分桶统计有何差异|

MAKE 的随机/预训练与冻结/联合训练四组策略属于后续专项矩阵，不能仅凭 C5 对 C0 将所有收益归因于预训练。

## 第二部分：如何选择和理解历史

|方法|配置索引|关键比较|
|---|---|---|
|最近 K 条 + 普通注意力|R0|近期行为参照|
|内容检索 + 普通注意力|R1|R1 对 R0：目标相关选择|
|内容检索 + 普通注意力 + 相似度统计|R2|R2 对 R1：统计分支|
|内容检索 + 语义感知注意力|R3|R3 对 R1：语义注意力|
|内容检索 + 语义注意力 + 相似度统计|R4|分别对 R2、R3：额外贡献|
|内容检索 + 长历史统计分支|R5|对 R2：长历史 ID 注意力的额外贡献|

R5 仍保留公共 ID 和短历史分支，不是全模型 content-only。类目和 ID 检索、更多历史长度等对照后续单列。当前核心矩阵均为 L200，MUSE 的 K=50；不能把 L1000 的历史收益混入本轮模块消融。

两个项目共享数据和训练约束，但模型主干细节及相似度分桶定义不同。跨项目最佳分数不能直接解释为单变量算法升级。

## 执行与复用

入口为 `scripts/run_shared_core.py`，参数包括共享存储、内容项目路径、同种子的内容预训练运行、直方图缓存和新输出目录。`--plan-only` 执行来源及配置核验并输出计划，不启动训练；正式运行保存共同协议摘要、逐模型最终配置及队列状态，串行训练，失败即停止。

seed=42 矩阵包含 12 组，11 组新训练。C6 复用已独立审计的 batch=256、两类学习率 0.001 运行：检查除名称外的完整配置、预测与报告摘要、数据清单及当前训练/模型源码摘要，记录原产物路径；没有复制、重新命名或重复训练其权重。汇总与审计时必须按计划中的复用路径读取，不能假定每项均位于新输出目录。

内容预训练继续使用既有单独协议，以验证 GAUC 最大、并列取最早轮的规则选择同种子检查点，并验证摘要。不同预训练预算和最终选点均保留。下游共同协议不会悄悄改变预训练 batch。

执行前核验 12 个配置共同参数及历史窗口，MUSE 现有 24 项测试通过。完成训练不等于效果审计完成；完整预测仍需对齐源行、标签和用户并重算指标，再进行预先定义的配对比较。保留测试集未评估，旧 batch=32 结果与新主表分开。
