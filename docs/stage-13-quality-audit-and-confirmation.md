## 确认队列

1. R4、seed 2026、batch 256，固定候选学习率。
2. R4、seed 2026、batch 512，固定候选学习率。
3. C6、seed 42、batch 256，使用同一候选学习率。
4. C6、seed 42、batch 512，使用同一候选学习率。

四组串行训练及独立预测审计均已完成。R4 维持 L1000，C6 维持其原 L200 协议，因此跨模型不能直接比较绝对分数来归因。C6 复用原 seed 42 第三轮MAKE 推荐预训练检查点，冻结分支不变，仅改变下游 batch 和 dense LR；这不是对MAKE 推荐预训练 batch 的评估，更不等于全链路训练配置已确定。

确认入口 `run_batch_confirmation.py` 校验筛选报告摘要、数据清单和 C6 权重摘要，保存四组最终配置快照，失败即停止后续任务。两个训练入口均可按配置启用实际设备剩余量和 CPU 资源检查；模型结构和前向公式未改动。代码测试：多模态表示集成项目 30 项、MUSE 项目 24 项通过。

R4 第二种子检查训练随机性，C6 检查参数选择的跨模型适用性；二者仍使用原验证人群，不是独立数据泛化测试。确认与预测审计已完成，后续仍需决定是否扩大数据规模及统一重跑关键对照。最终 batch、学习率、数据规模未冻结；未评估保留测试集。


## 确认结果及解释

四组候选和两组旧协议参考均通过完整验证行、标签、用户分组与指标重算检查。模型依赖摘要保持一致；训练入口增加资源记录。审计核对检查点存在性及原报告重载误差，没有重新加载全部权重。详细数据、预测摘要与配对结果见[确认审计](../reports/batch-confirmation-050-audit.json)。

|方法与种子|batch|GAUC ↑|LogLoss ↓|训练分钟|
|---|---:|---:|---:|---:|
|MUSE 完整适配组合，2026|32（旧协议）|0.593198|0.388179|60.49|
|MUSE 完整适配组合，2026|256|0.592868|0.388985|20.78|
|MUSE 完整适配组合，2026|512|0.592349|0.390302|19.05|
|相似度统计 + MAKE，42|32（旧协议）|0.588938|0.387596|37.93|
|相似度统计 + MAKE，42|256|0.590387|0.387376|7.77|
|相似度统计 + MAKE，42|512|0.590414|0.387116|5.76|

训练时间不包括多模态分支预训练、评估及预测保存，且受运行时系统状态影响。两类方法历史长度不同，表中只能在各自方法内比较。

- **MUSE 完整组合：**256 相比旧协议约快 2.9 倍，但 GAUC 点估计下降 0.000330，95% 用户配对区间为 [-0.001295, 0.000643]；跨零不等于证明等效。512 相比 256 的 GAUC 差为 -0.000518，区间 [-0.000941, -0.000072]，同时 LogLoss 更差，只节省约 1.7 分钟。因此本次确认不支持直接统一采用 512。
- **相似度统计 + MAKE：**256、512 相比旧协议的 GAUC 差区间分别为 [0.000851, 0.002110]、[0.000789, 0.002158]。512 相比 256 的差为 0.000027，区间 [-0.000373, 0.000411]；本次结果更支持将 512 视为此模型的效率候选，但尚缺跨种子确认。

旧协议与候选同时改变 batch 和 dense LR，收益不能单独归因于 batch。256 与 512 的其他训练配置一致。配对区间使用 2000 次用户 bootstrap，条件于已训练模型及同一验证人群，未做六次比较的多重校正；不能替代训练种子波动或独立测试证据。MAKE MAKE 推荐预训练仍使用原检查点，结果仅涉及下游训练。

本轮属于训练方案选择，不新增方法贡献。后续应同时考虑排序与概率预测质量，不以验证集单个最高 GAUC 冻结方案。当前仍使用 5% 用户队列，最终数据规模、统一训练协议及保留测试结果尚未确定。方法故事线与编号说明见[实验导读](https://github.com/IJustWannaFindMyPeace/taobao-mm-content-integration/blob/main/docs/experiment-guide.md)。
