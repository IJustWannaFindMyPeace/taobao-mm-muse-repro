# 共同协议下的长历史与检索策略对照

核心 L200 三种子已完成，见[三种子汇总](shared-core-three-seed-results.md)。本阶段保持同一 5% 队列、batch=256、两类学习率 0.001、单轮预算、K=50，将候选历史扩大为 L1000。先执行 seed=42 并审计，再补其他种子。

|方法|用途|
|---|---|
|内容检索 + 普通注意力|与同种子 L200 比较历史长度作用|
|内容检索 + 语义注意力 + 统计|与 L200 比较；作为增强聚合下的检索参照|
|同类目检索 + 增强聚合|内容检索相对类目选择|
|商品/类目 ID 检索 + 增强聚合|内容检索相对组合 ID 空间选择|
|商品 ID 检索 + 增强聚合|区分单商品 ID 与商品/类目 ID 检索|

增强聚合均为语义感知目标注意力与相似度统计，所以三类检索对照并非“完全不用内容”的基线。模型为公共主干适配实现，不冒称原始 SIM 完整模型。

seed=42 的内容检索完整组合复用质量筛选中 batch=256、两类学习率 0.001 的完整运行。入口 `run_shared_retrieval.py` 比对除名称外配置、数据清单、预测与报告摘要、当前实现源码，记录原产物路径；其余四组新训练。复用模型虽来自筛选过程，仍属于验证证据，不能称为独立测试。seed=42 训练及七组相关预测核验、六项配对分析均已完成。

后续预定义比较为：普通聚合及完整组合各自 L1000−L200、L1000 完整组合−普通聚合，以及内容完整组合分别对三个增强检索基线。最终完整预测需重新核对用户、标签、源行和指标，再计算配对区间。训练条件保持固定，不用旧 batch=32 基线拼接新主表。


## 首个种子的结果

|比较|GAUC 差值|95% 用户配对区间|
|---|---:|---|
|普通聚合：L1000 − L200|+0.002956|[0.001437, 0.004468]|
|完整组合：L1000 − L200|+0.002684|[0.001002, 0.004364]|
|L1000：完整组合 − 普通聚合|+0.016733|[0.014989, 0.018542]|
|内容检索 − 类目检索|+0.005077|[0.003399, 0.006689]|
|内容检索 − 商品/类目 ID 检索|+0.004723|[0.003231, 0.006241]|
|内容检索 − 商品 ID 检索|+0.007398|[0.005769, 0.009046]|

六项比较的 AUC 点估计均增加、LogLoss 均降低，GAUC 用户配对区间均为正。这支持在此种子和队列下更长历史及内容检索的价值，不替代跨种子稳定性证据。普通聚合与完整组合的比较同时增加两个模块，不将差异全部归因于语义注意力。

审计核对七组完整预测（含两个 L200 参照）的源行、标签、用户、重算指标、训练步数、配置快照、公共源码与检查点存在性；训练报告重载误差为零，本次不重新加载权重。长度比较仅改变 L；检索策略比较固定增强聚合及其他配置，仅改变检索策略。后者的候选不足、缺失回退等属于策略的一部分。

每项区间使用 2000 次用户 bootstrap，六次比较未作多重校正；条件于固定模型及验证队列，不是独立测试或不同训练人群的证据。完整明细见[首种子审计](../reports/shared-retrieval-v1-seed42-audit.json)。
