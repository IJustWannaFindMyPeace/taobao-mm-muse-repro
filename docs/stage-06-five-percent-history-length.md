# 阶段 6：5% 数据上的历史长度端点

## 问题与控制变量

检索能够访问更多历史，不等于一定选到更有帮助的行为。本阶段对 R1（内容检索 + ID 注意力）和 R4（完整组合）分别比较历史长度 200 与 1000。

沿用阶段 5 的 5% 数据存储、seed 42、batch size 32、完整一轮训练、完整验证集。训练词表在两个长度下均来自同一份完整训练用户历史，避免随长度改变词表。短历史固定为 50，检索 K 固定为 50；修改的是 GSU 可搜索的历史范围，而不是 ESU 聚合条数。

配置仅改变 `history_length` 和实验名称，其他超参数一致。固定内容向量、缺失回退、并列排序规则和掩码处理沿用核心实现。

## 对照关系

|比较|要回答的问题|
|---|---|
|R1-L1000 − R1-L200|普通 ID 聚合下，增加检索历史是否有收益|
|R4-L1000 − R4-L200|完整 ESU 下，增加检索历史是否有收益|
|R4-L1000 − R1-L1000|固定长历史时，增强 ESU 的整体效果|

第三项同时改变 SimTier 与 SA-TA，不用于将效果单独归因于某一个模块。模块归因使用阶段 5 的完整消融关系。

## 解释边界与下一阶段

区间以固定模型和验证人群为条件，不反映训练种子、子集选择和配置选择的不确定性，三组比较未做多重比较校正。该端点比较不能称为完整的 50/200/500/1000 长度扫描，也不覆盖工业十万级历史。

与 1% 阶段尚未确认长度收益的结果并不矛盾：数据量和验证人群均已改变，不能将差异仅归因于增加训练数据。下一阶段固定当前 5% 数据协议，补充 seed 2026、3407 的核心实验与长度端点，检查收益方向及模型排名是否稳定；其他基线、MAKE 策略对照和中间长度仍需分别补齐。

核心长度 200 的三种子已完成，见阶段 7。长度 1000 的 seed 42、2026 两组端点均已完成并通过预测审计；seed 3407 的两组端点也已完成，三种子汇总见下文。

每组保存预测的标签、源行和用户分组均与数据存储一致，重算指标与训练报告一致。配对 bootstrap 使用 2,000 次用户重采样，随机种子 2026；上述区间以固定模型及验证人群为条件，不包含训练种子不确定性，未做多重比较校正。
