# 内容余弦与内容＋ID 余弦检索对照

目的：检验在固定增强 ESU 的条件下，额外引入 ID 检索分数是否改善效果，以及代价是否值得。对应 [MUSE §3.1 表 2](https://arxiv.org/html/2512.07216v1) 的余弦融合思路；这是明确缺失策略的本地适配，不覆盖所有复杂检索器。

## 运行前固定的规格

- 数据、词表及划分沿用共同 5% 队列；L=1000、K=50、batch=256、单轮，种子 42/2026/3407。学习率、优化器与资源门槛不变。
- 内容检索参考为已有完整增强模型。融合检索采用 `cos(content_target, content_history) + cos(item_ID_target, item_ID_history)`，两路分别 L2 归一化，等权相加，不搜索权重，不加入类目 ID。
- 候选资格与内容参考完全一致：目标有内容时只选有效且有内容的历史；目标内容缺失时按近期历史回退。ID 未知、padding 或零向量时，该行为 ID 分数贡献为零，不改变候选集合。此缺失策略是本地选择，不声称来自论文。
- 保留行为重复计数、稳定排序及同分优先近期的规则。不足 K 的位置显式 mask。
- ID 向量与 CTR 主干共享，由下游反向传播训练；Top-K 本身不求导。选中后在梯度上下文重新查表。没有独立的可学习检索参数，也不声称点击损失能直接优化离散筛选。
- ESU、短历史、公共特征与初始化不变。ESU 使用原内容相似度，不使用两路分数之和，以便只改变检索规则。

## 验证与执行顺序

先验证排序改变、缺失与 padding、同分、全无效行为、内容参考等价和共享 ID 梯度；再以共同 batch 做短资源检查。通过后串行训练三个种子。资源失败即停止，不自动缩小 batch 或样本规模。

主比较是每个种子的融合检索减内容检索，完整验证 AUC、GAUC、LogLoss，用户配对区间及三种子波动。资源报告包含训练吞吐、显存和内存。已有内容参考复用前须核对模型、数据、配置与实现差异；增加新分支不作为旧模型行为未变的唯一凭据。

不得因增量区间跨零而宣布统计等效，也不能由一种融合规则推出所有复杂检索无用。测试集不参与设计或选择。

## 核验与运行状态

17 项相关检查通过，包括参考模型前向与梯度精确一致、排序变化、未知 ID、内容缺失回退、padding、同分及全无效历史处理。共享 ID 分支仍获得下游梯度。

共同 batch=256 资源短测通过：峰值分配显存 8.175 GiB、最低 CUDA 空闲 1.421 GiB、进程峰值 RSS 5.903 GiB、系统最低可用内存 11.440 GiB。测量 16,384 条曝光，约 389 条/秒；约 94% 测量时间在特征读取，短测不能直接代表完整轮吞吐。[资源报告](../reports/fused-retrieval-resource-v1.json)。

三种子串行训练与自动审计队列已启动，当前尚无完整效果结论。入口 `scripts/run_fused_retrieval.py` 校验共同配置、数据、既有参考报告/预测摘要和源文件；内容参考使用未修改的 MUSEModel，新增基线分支另行测试，不据源码总摘要变化要求重复训练旧参考。每组完整训练后核对所有验证源行、标签、用户及重算指标，再执行用户配对比较。任何失败停止后续任务，不自动调整 batch。
