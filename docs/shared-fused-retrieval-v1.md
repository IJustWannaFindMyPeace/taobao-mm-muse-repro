# 多模态余弦与多模态表示＋ID 余弦检索对照

> 文档性质：阶段记录／历史协议。本文中的规模、配置、验证结果及待办状态属于记录时点；当前结果以[主测试](final-test-results.md)、[补充测试](supplementary-test-results.md)和[覆盖说明](current-reproduction-status.md)为准。

目的：检验在固定增强 ESU 的条件下，额外引入 ID 检索分数是否改善效果，以及代价是否值得。对应 [MUSE §3.1 表 2](https://arxiv.org/html/2512.07216v1) 的余弦融合思路；这是明确缺失策略的本地适配，不覆盖所有复杂检索器。

## 运行前固定的规格

- 数据、词表及划分沿用共同 5% 队列；L=1000、K=50、batch=256、单轮，种子 42/2026/3407。学习率、优化器与资源门槛不变。
- 多模态检索参考为已有完整增强模型。融合检索采用 `cos(content_target, content_history) + cos(item_ID_target, item_ID_history)`，两路分别 L2 归一化，等权相加，不搜索权重，不加入类目 ID。
- 候选资格与多模态表示参考完全一致：目标有多模态表示时只选有效且有多模态表示的历史；目标多模态表示缺失时按近期历史回退。ID 未知、padding 或零向量时，该行为 ID 分数贡献为零，不改变候选集合。此缺失策略是本地选择，不声称来自论文。
- 保留行为重复计数、稳定排序及同分优先近期的规则。不足 K 的位置显式 mask。
- ID 向量与 CTR 主干共享，由下游反向传播训练；Top-K 本身不求导。选中后在梯度上下文重新查表。没有独立的可学习检索参数，也不声称点击损失能直接优化离散筛选。
- ESU、短历史、公共特征与初始化不变。ESU 使用原语义相似度，不使用两路分数之和，以便只改变检索规则。

## 验证与执行顺序

先验证排序改变、缺失与 padding、同分、全无效行为、多模态表示参考等价和共享 ID 梯度；再以共同 batch 做短资源检查。通过后串行训练三个种子。资源失败即停止，不自动缩小 batch 或样本规模。

主比较是每个种子的融合检索减多模态检索，完整验证 AUC、GAUC、LogLoss，用户配对区间及三种子波动。资源报告包含训练吞吐、显存和内存。已有多模态表示参考复用前须核对模型、数据、配置与实现差异；增加新分支不作为旧模型行为未变的唯一凭据。

不得因增量区间跨零而宣布统计等效，也不能由一种融合规则推出所有复杂检索无用。测试集不参与设计或选择。

## 核验与运行状态

17 项相关检查通过，包括参考模型前向与梯度精确一致、排序变化、未知 ID、多模态表示缺失回退、padding、同分及全无效历史处理。共享 ID 分支仍获得下游梯度。

共同 batch=256 资源短测通过：峰值分配显存 8.175 GiB、最低 CUDA 空闲 1.421 GiB、进程峰值 RSS 5.903 GiB、系统最低可用内存 11.440 GiB。测量 16,384 条曝光，约 389 条/秒；约 94% 测量时间在特征读取，短测不能直接代表完整轮吞吐。[资源报告](../reports/fused-retrieval-resource-v1.json)。

三种子串行训练与自动预测审计已全部完成，保留测试集未评估。入口 `scripts/run_fused_retrieval.py` 校验共同配置、数据、既有参考报告/预测摘要和源文件；多模态表示参考使用未修改的 MUSEModel，新增基线分支另行测试，不据源码总摘要变化要求重复训练旧参考。每组完整训练后核对所有验证源行、标签、用户及重算指标，再执行用户配对比较。任何失败停止后续任务，不自动调整 batch。


## 三种子验证结果

|种子|纯多模态表示 GAUC|多模态表示＋ID GAUC|GAUC 差|95% 用户配对区间|
|---|---:|---:|---:|---|
|42|0.592202|0.588716|-0.003486|[-0.004831, -0.002141]|
|2026|0.593928|0.589147|-0.004781|[-0.006178, -0.003435]|
|3407|0.593913|0.589498|-0.004415|[-0.005789, -0.003001]|

融合减纯多模态表示的 GAUC 三种子平均为 −0.004227，三个用户配对区间均为负；AUC 均下降，LogLoss 均上升。本配置下，额外加入共享商品 ID 余弦没有收益，反而损害效果。结果仅针对等权求和、当前缺失规则和一轮训练协议，不推广到其他融合权重、可学习检索或所有复杂方法。

每组完整训练 3,052,475 条曝光，完整验证 768,773 条。训练耗时约 21–23 分钟/组，峰值分配显存约 8.175 GiB；三组最大进程 RSS 约 14.043 GiB，最低系统可用内存约 9.166 GiB，最低 CUDA 空闲约 1.371 GiB，均通过既定门槛。短资源测试受数据读取影响较大，不用于宣称完整训练速度。旧参考运行未与新增运行做交替计时，耗时差不能直接归因为检索算法成本。

每个 GAUC 区间使用 2000 次用户配对 bootstrap，未作多重校正；三个种子共享用户队列，不是三个独立数据集。所有预测通过源行、标签、用户、重算指标核验。[机器可读汇总](../reports/shared-fused-retrieval-v1-three-seed-summary.json)。
