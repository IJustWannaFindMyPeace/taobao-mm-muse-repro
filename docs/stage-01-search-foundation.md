# 共享主干迁移与 GSU 检索检查

## 来源与衔接

依据 [MUSE §4.2](https://arxiv.org/html/2512.07216v1#S4.SS2) 和[官方检索函数](https://github.com/alimama-tech/MUSE/blob/main/utils/utils.py)，GSU 使用固定内容的余弦相似度选取 Top-K 历史。本项目先实现 R0（最近 K 条）和 R1（内容 Top-K），二者使用相同的 ID 目标注意力作为长历史 ESU。

前序项目的 `c0.py`、`feature_store.py` 和 `metrics.py` 按字节迁入本仓库，来源版本及校验和见[共享代码清单](../reports/shared-code-provenance.json)。代码独立可用，无跨仓库运行时导入；后续更新需要重新核验清单和预测一致性。

使用同一特征存储与原 C0 检查点，本仓库 C0 在前 32 条完整验证记录上的预测与前序保存结果完全相同，最大绝对误差为零。该检查验证迁移链路，不表示已经复核全部验证预测。

## 检索边界与适配

- 以行为位置为单位检索，重复点击同一商品仍保留为多条行为。
- 使用显式 ID-valid、内容可用性和非零向量 mask。真实零余弦分数有效，可以排在负余弦之前。
- 官方本地参考函数将零相似度改为 -1.1 排除 padding。本实现不采用该启发式，避免误排除真实正交向量。
- 并列分数优先最近行为；通过逆序位置和稳定排序实现，输出按分数降序。当前 L≤1000，不宣称稳定全排序适合工业 100K 延迟预算。
- 目标内容缺失时回退到最近的有效 ID 行为；目标有内容时只检索有内容的有效历史。候选不足 K 时，剩余位置携带 false mask，聚合前置零。
- Top-K 索引计算不参与梯度；选中商品的 ID embedding 和 ESU 参数仍正常训练。

回退策略和并列处理属于本地适配，后续检索对照统一采用。内容缺失不等同于 padding，也不以 OOV ID 自动删除行为。

## 模型结构

公共短分支保持最近 50 条原始历史，不受 GSU 结果影响；长分支只对选中的 50 条行为查找 ID/类目 embedding 并执行目标注意力。公共 MLP 和全部可训练参数形状与前序 C0 一致。R0 不是独立 DIN 基线。

当 K=L 时，最近历史模型与 C0 的输出在数值容差内一致。当前不包含 SA-TA、MUSE 的可学习 SimTier 或完整 R4，也未添加官方代码中的均值旁路。

## 检查入口与结果

在已验证的 PyTorch CUDA 环境中，从本仓库运行：

```powershell
python -m unittest discover -s tests
python scripts/probe_search.py --store <shared-feature-store> --c0-run <original-c0-run> --output-dir <fresh-output-directory>
```

10 项测试通过，包括零/负相似度、padding、重复行为、不足 K、空历史、缺失目标回退、随机标量排序参考、完整历史等价性及指标契约。

四个配置分别完成 20 步、640 条训练记录，参数更新和有限梯度检查通过：

|检索|L|K|Batch|峰值分配显存 MiB|
|---|---:|---:|---:|---:|
|最近行为|200|50|32|2835.93|
|内容余弦|200|50|32|2835.93|
|最近行为|1000|50|32|2874.73|
|内容余弦|1000|50|32|2874.73|

完整环境、耗时及代码校验和见[资源报告](../reports/search-resource-probe.json)。短时检查含初始化、CPU 查表和缓存状态差异；最近行为配置也走公共内容读取路径，不能据此比较纯检索耗时。显存为 PyTorch 分配统计，不包含全部驱动和 CPU 内存。

本阶段没有方法效果评估，未访问测试集。下一步实现 SA-TA 与 MUSE SimTier，再测完整 R4，并确定训练规模。当前结果不足以确定两项目的最大共同数据量。
