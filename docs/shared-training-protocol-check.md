# 共同训练方案：限定范围的学习率确认

主数据规模已选定为两个项目共用的 5% 用户队列。本阶段只确认训练方案，不增加推荐模块，不改变数据规模，也不使用保留测试集。

## 尚未解决的问题

batch=256 已通过完整训练资源验证，速度明显优于 32。但先前按首个种子最高 GAUC 选择的 dense LR=0.0002，在 MUSE 第二个种子上出现 AUC 和 LogLoss 下降。最高 GAUC 候选不一定适合作为共同协议，因此需检查原 dense LR=0.001 的跨种子、跨模型表现。

## 两组新增运行

|方法|种子|batch|ID 学习率|普通网络学习率|历史长度|
|---|---:|---:|---:|---:|---:|
|多模态检索 + 语义注意力 + 相似度统计|2026|256|0.001|0.001|1000|
|相似度统计 + MAKE|42|256|0.001|0.001|200|

每组训练一轮 3,052,475 条曝光，验证完整 768,773 条记录。与各自已审计的 batch=256 对照仅改变普通网络学习率及运行名称。MAKE 复用同一冻结MAKE 推荐预训练检查点，不将该运行误称为预训练全链路调整。已有 MUSE seed=42、相同参数结果直接复用，不重复训练。

运行入口 `scripts/run_shared_protocol_check.py` 从已审计配置派生候选，校验数据清单与多模态表示权重摘要，保存配置快照，串行执行并在失败后停止；不自动降低 batch。两组训练、完整预测审计及四项配对比较均已完成；选择与局限如下。

## 决策原则

同时报告 AUC、GAUC、LogLoss、训练时间和资源余量。相对低学习率对照用于判断该变量的影响，相对旧 batch=32、学习率=0.001 的参考用于判断批大小变化。区分单种子配对不确定性与跨种子波动；验证区间跨零不等于已经证明等效。

本轮不再增加 batch 或学习率网格。若出现指标冲突，保留冲突并明确选择理由，不在看到结果后编造等效阈值；如果证据仍不足以接受共同大 batch，则保留既有协议或设计有明确假设的有限确认。共同方案确定后，核心消融使用相同下游训练条件，不将不同协议的最好结果混为方法主表。

参考：[前轮确认结果](stage-13-quality-audit-and-confirmation.md)、[共同规模决策](https://github.com/IJustWannaFindMyPeace/taobao-mm-content-integration/blob/main/docs/shared-scale-decision.md)。


## 选择：共同下游协议 v1

采用 **5% 用户队列、batch=256、SparseAdam 学习率 0.001、AdamW 学习率 0.001、weight decay=0、主对照训练一轮**。ID 维度仍为 16，种子集合为 42/2026/3407。两个仓库保存完全一致的 `configs/shared-downstream-protocol-v1.json`。此文件是后续配置生成的共同约束，不能直接作为模型训练配置；现有历史配置未被覆盖，新运行必须显式派生并保存最终快照。

该选择是可执行的资源与质量折中，不声称找到全局最优或证明统计等效。MUSE 已有两个种子的该参数证据，多模态融合目前只有一个；核心矩阵后续统一使用本协议确认跨模型和跨种子表现，不再为单个模型选择专属主表参数。

|方法与种子|旧 batch=32 GAUC|新 batch=256 GAUC|新−旧 GAUC 95% 配对区间|旧→新训练分钟|
|---|---:|---:|---|---|
|MUSE 完整组合，2026|0.593198|0.593928|[-0.000110, 0.001576]|60.49→24.62|
|相似度统计 + MAKE，42|0.588938|0.590299|[0.000766, 0.001990]|37.93→7.95|

相对旧协议，两行的 AUC 均提高，LogLoss 均降低。已有 MUSE seed=42 的新协议 GAUC 为 0.592202，略低于旧协议 0.592314，AUC 和 LogLoss 点估计改善；不隐去这个 GAUC 下降，也不宣称所有种子和指标都提升。

相对 batch=256、dense LR=0.0002，恢复 LR=0.001 的 MUSE seed=2026 GAUC 差为 +0.001061，区间 [0.000277, 0.001854]，AUC 与 LogLoss 同时改善。多模态融合 GAUC 差为 -0.000088，区间 [-0.000564, 0.000406]，AUC 与 LogLoss 改善。首个 MUSE 种子的低学习率 GAUC 更高，已在前轮完整筛选表保留；选择原学习率是综合取舍，不是按两个种子逐个挑最高 GAUC。

## 审计边界与后续执行

六组参考/候选完整核对 768,773 条验证记录的源行、用户和标签，重算 AUC/GAUC/LogLoss 与训练报告一致，训练曝光、步数、配置快照及公共模型源码摘要通过检查。检查点存在，训练时重载误差均为零，本次未重新加载全部权重。四组配对区间各用 2000 次用户 bootstrap，未做多重校正，仅条件于固定模型和同一验证队列；没有独立数据确认，也没有预先设定的等效检验。

批大小对照保持学习率相同；学习率对照保持 batch=256，分别报告，避免混淆。训练耗时受系统负载影响且不含评估与MAKE 推荐预训练。审计报告记录的是作出决策前的状态，其中 `final_protocol_frozen=false` 不会被事后篡改；本节及共同协议文件记录后续的采用决定。

下一阶段先统一重跑两项目的核心对照，再补关键独立基线、长度与训练策略对照。已完成且配置与模型来源完全一致的运行可以经审计复用，不能仅凭名字相同复用。原 batch=32 三种子结果保留为旧协议验证证据，与新主表分开。MAKE 多模态分支预训练保持既有单独协议和选点规则，额外计算成本显式报告；预训练轮数消融、ID 多轮诊断等研究变量不受主对照一轮限制。

本轮不扩大调参网格，未读取保留测试集指标。测试协议与最终报告仍需在主对照完成后冻结。详见[本轮审计](../reports/shared-protocol-check-050-audit.json)。
