# 共同训练方案：限定范围的学习率确认

主数据规模已选定为两个项目共用的 5% 用户队列。本阶段只确认训练方案，不增加推荐模块，不改变数据规模，也不使用保留测试集。

## 尚未解决的问题

batch=256 已通过完整训练资源验证，速度明显优于 32。但先前按首个种子最高 GAUC 选择的 dense LR=0.0002，在 MUSE 第二个种子上出现 AUC 和 LogLoss 下降。最高 GAUC 候选不一定适合作为共同协议，因此需检查原 dense LR=0.001 的跨种子、跨模型表现。

## 两组新增运行

|方法|种子|batch|ID 学习率|普通网络学习率|历史长度|
|---|---:|---:|---:|---:|---:|
|内容检索 + 语义注意力 + 相似度统计|2026|256|0.001|0.001|1000|
|相似度统计 + MAKE|42|256|0.001|0.001|200|

每组训练一轮 3,052,475 条曝光，验证完整 768,773 条记录。与各自已审计的 batch=256 对照仅改变普通网络学习率及运行名称。MAKE 复用同一冻结内容预训练检查点，不将该运行误称为预训练全链路调整。已有 MUSE seed=42、相同参数结果直接复用，不重复训练。

运行入口 `scripts/run_shared_protocol_check.py` 从已审计配置派生候选，校验数据清单与内容权重摘要，保存配置快照，串行执行并在失败后停止；不自动降低 batch。两组已启动，结果待完成和独立预测审计，当前不能宣布新方案胜出。

## 决策原则

同时报告 AUC、GAUC、LogLoss、训练时间和资源余量。相对低学习率对照用于判断该变量的影响，相对旧 batch=32、学习率=0.001 的参考用于判断批大小变化。区分单种子配对不确定性与跨种子波动；验证区间跨零不等于已经证明等效。

本轮不再增加 batch 或学习率网格。若出现指标冲突，保留冲突并明确选择理由，不在看到结果后编造等效阈值；如果证据仍不足以接受共同大 batch，则保留既有协议或设计有明确假设的有限确认。共同方案确定后，核心消融使用相同下游训练条件，不将不同协议的最好结果混为方法主表。
